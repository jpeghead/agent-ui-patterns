# Copy

The sentences that work in agent interfaces, the ones that don't, and why. Most of the trust in these patterns is carried by a few dozen words.

## Rules

- **Facts with numbers in them.** "Changed 1 file · +6 −2 · 48 tests pass." A number can be checked; an adjective cannot.
- **Verbs for steps, nouns for options.** Steps are what the agent does ("Run the suite"). Options are what the person picks ("Button · 41 uses").
- **One sentence per job.** What happened. What did not happen. What you can do. Each gets its own sentence; none of them gets two.
- **The literal thing, not its description.** The command, the error line, the file path. The description is the agent's opinion; the thing is evidence.
- **Consequences on buttons.** "Revert the edit · Back to green. The coupon bug stays." A button that does not say what it costs is asking for trust it has not earned.
- **No exclamation marks, no apologies, no reassurance.** "Nothing was deployed" reassures by being true.
- **The agent in the third person by name**, or "it". Never "I" for the product's own interface chrome. "I" belongs to the model's answers, where it is graded.

## Words that work

| Instead of | Say |
|---|---|
| Something went wrong | Build failed at step 2 of 3 |
| An error occurred | Type error in src/cart/total.ts:14 |
| Processing… | Run the suite (with the tool line under it) |
| Almost done | working… (and the steps) |
| Are you sure? | Touches 1,204 files · Reversible: yes |
| Allow all | Allow `rm -rf build/` this session |
| Don't ask again | (nothing; rules are set in settings) |
| Cancel | Deny · Claude will run the tests against the stale build |
| I think it was around 2020 | WWDC 2020 · from the Spin case study |
| I'm not sure | I don't know the exact date in June |
| Please verify this information | (nothing; the grades say which parts to verify) |
| Clarification needed | Needs a decision |
| Which one should I use? | Two button components exist. Which is canonical? The page uses neither yet, so this choice sets the pattern. |
| I assumed X | (never; ask) |
| Done! | Changed 1 file · +9 −9 · 12 tests pass · decision recorded: Button |

## Sentences from the prototypes, and why they are shaped that way

**"Claude wants to run a command · to clear a stale build before the test run."**
Actor, verb, object, then the reason after a middle dot. The reason is the agent's claim about itself, kept short so a wrong reason is visible against the command below it.

**"Yes. Both are regenerated by the next build."**
The answer first, the reason second. People scanning read "Yes" and move on; people deciding read why.

**"Denied. Claude will run the tests against the stale build and tell you if that mattered."**
A denial that keeps a promise. The agent says what it will do instead, and that it will report on the consequence.

**"Nothing was deployed."**
The sentence people are looking for after a failure. It goes before the ways forward.

**"Smallest change. Keeps the fix."**
Two fragments, each a cost or a benefit. A button's second line should be readable in the time it takes to move a hand to it.

**"I don't know the exact date in June."**
The unknown is specific. "I don't know" plus the exact thing not known is more useful than any hedge.

**"It will not guess. Nothing is edited until you answer."**
The contract, as two short promises. This line is what lets the person walk away from the question.

**"The question and the answer stay in the log, so the next run won't ask again."**
Says what the product will do with the decision. Decisions that vanish train people to stop making them.
